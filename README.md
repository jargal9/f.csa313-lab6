# F.CSA313 — Лаборатори №6: Тест тохиолдол боловсруулах — Category-Partition ба PICT

> **B232270019 О. Оюунжаргал**
## Хэсэг A. Category-Partition

### A1. Сонголт ба төлөөлөх утгууд

| Параметр | Сонголт | Төлөөлөх утга |
|---|---|---|
| From | Хүчинтэй данс | Valid |
| From | Царцаагдсан данс | Frozen |
| From | Байхгүй данс | Missing |
| To | Хүчинтэй өөр данс | Valid |
| To | Байхгүй данс | Missing |
| To | From-той ижил данс | SameAsFrom |
| Amount | Тэг буюу тэгээс бага | Zero |
| Amount | Хэвийн дүн | Normal |
| Amount | Үлдэгдлээс их | OverBalance |
| Amount | Өдрийн лимитээс их | OverLimit |
| Currency | Дансны валюттай ижил | Same |
| Currency | Өөр валют | Different |

**Далд орчны сонголтууд:** дансны үлдэгдэл, өдрийн лимитийн үлдсэн хэмжээ, валют хөрвүүлэх ханш. Amount-ийн үлдэгдэл болон лимиттэй харьцах төлөвийг хөрвүүлсний дараах дүнгээр тодорхойлно.

### A2. Хязгаарлалт ба үндэслэл

| Сонголт | Тэмдэглэгээ | Үндэслэл |
|---|---|---|
| From = Valid | [SINGLE] | Хэвийн шилжүүлэгт хүчинтэй эх данс шаардлагатай. |
| From = Frozen | [ERROR] | Царцаагдсан данснаас шилжүүлэг хийх ёсгүй. |
| From = Missing | [ERROR] | Байхгүй эх данснаас шилжүүлэг хийх боломжгүй. |
| To = Valid | [SINGLE] | Амжилттай шилжүүлэгт хүчинтэй хүлээн авагч шаардлагатай. |
| To = Missing | [ERROR] | Хүлээн авагчийн данс олдохгүй. |
| To = SameAsFrom | [ERROR] | Нэг данснаас өөр рүүгээ шилжүүлэхийг хориглоно. |
| Amount = Zero | [ERROR] | Дүн тэг буюу тэгээс бага бол шилжүүлэг хүчингүй. |
| Amount = Normal | [SINGLE] | Эерэг, үлдэгдэл болон лимитэд багтах дүнг төлөөлнө. |
| Amount = OverBalance | [ERROR] | Шилжүүлэх дүн үлдэгдлээс их байна. |
| Amount = OverLimit | [ERROR] | Шилжүүлэх дүн өдрийн лимитээс их байна. |
| Currency = Same | [SINGLE] | Валют хөрвүүлэлтгүй хэвийн шилжүүлгийг төлөөлнө. |
| Currency = Different | [IF] | Валют өөр үед хөрвүүлэлт хийж, шалгалтыг хөрвүүлсний дараах дүнгээр хийнэ. |

**Сонгосон алдааны давуу эрэмбэ:** ERROR_NO_FROM → ERROR_FROZEN → ERROR_NO_TO → ERROR_SAME_ACCOUNT → ERROR_BAD_AMOUNT → ERROR_INSUFFICIENT → ERROR_LIMIT.

Энэ эрэмбэ нь тодорхойлолтод заагаагүй олон алдааны үед тестийн хүлээгдэх үр дүнг нэг мөр болгох зорилготой таамаглал юм.

#### Хязгаарлалтын тооцоо

Бүрэн комбинацын тоо:

3 × 3 × 4 × 2 = 72.

From = Missing үед Amount нь Normal биш байх 18 комбинац хасагдана. To = Missing үед мөн 18 комбинац хасагдана. Хоёр нөхцөл зэрэг биелэх 6 комбинац давхар хасагдсан тул буцаан нэмнэ.

Иймээс:

72 − 18 − 18 + 6 = 42.

**Бүрэн олонлог → хязгаарлалтын дараах олонлог: 72 → 42.**

Энэ тооцоо нь хоёр IF хязгаарлалтыг хэрэглэхэд үлдэх хүчинтэй комбинацын тоо юм. PICT-ийн pairwise гаралтын мөрийн тоо нь үүнээс өөр үзүүлэлт байна.

| 2 | Missing | Valid | Normal | Same | `200 {"result":"ERROR_NO_FROM"}` |
| 3 | Frozen | Valid | Normal | Same | `200 {"result":"ERROR_FROZEN"}` |
| 4 | Valid | Missing | Normal | Same | `200 {"result":"ERROR_NO_TO"}` |
| 5 | Valid | SameAsFrom | Normal | Same | `200 {"result":"ERROR_SAME_ACCOUNT"}` |

Давхар нөхцөлийн үр дүнг сонгосон давуу эрэмбээр тодорхойлов. Хүлээгдэх үр дүн нь бодит хэрэгжилтээс баталгаажаагүй, спецификацид тулгуурласан тестийн таамаглал юм.

## Хэсэг B. PICT-ийн үр дүн

### B1. Browser модель

| Хувилбар | Тестийн мөр | Бүрэн олонлог |
|---|---:|---:|
| 2-way | 10 | 144 |
| 3-way | 20 | 144 |

PICT-ийн 2-way гаралт 10 мөртэй бөгөөд лекцийн гараар хийсэн 9 мөрөөс нэгээр олон байна. PICT нь greedy алгоритмаар хослолуудыг хамруулдаг тул хамгийн цөөн мөрийн шийдлийг заавал олохгүй. 3-way хувилбар нь гурван параметрийн бүх боломжит гурвалсан утгын хослолыг хамруулах шаардлагатай учир 20 мөр үүсгэсэн.

### B2. Transfer модель

| Модель | Тестийн мөр | Happy path | Нэг мөр дэх сөрөг утгын дээд тоо |
|---|---:|---:|---:|
| transfer-nc.model | 13 | 1 | Хязгаарлаагүй |
| transfer.model | 12 | 0 | Хязгаарлалтаас хамаарна |
| transfer-neg.model | 16 | 2 | 1 |

`transfer-nc.model` нь алдаатай утгуудыг хооронд нь хослуулж болох тул нэг мөрөнд хэд хэдэн алдаа үүсгэж болно. `transfer.model` нь IF хязгаарлалтаар Missing данстай нөхцөлд Amount-ийн утгыг Normal болгож хязгаарласан. `transfer-neg.model` дахь `~` тэмдэглэгээ нь нэг мөрөнд хамгийн ихдээ нэг сөрөг утга оруулахад тусалдаг. Иймээс `~` тэмдэглэгээ нь сөрөг тестийн мөрүүдийг салгахад тустай боловч бизнесийн бүх хязгаарлалтыг орлохгүй.

### Бодит тест кейсүүд

#### TC-01 — Амжилттай шилжүүлэг
- **Setup:** A дансны үлдэгдэл 500,000₮; B данс хүчинтэй; өдрийн лимит хангалттай.
- **Оролт:** `{"from":"A","to":"B","amount":100000,"currency":"MNT"}`
- **Oracle:** HTTP 201, `{"result":"OK"}`.

#### TC-02 — Эх данс байхгүй
- **Setup:** `MISSING` ID-тай данс байхгүй; B данс хүчинтэй.
- **Оролт:** `{"from":"MISSING","to":"B","amount":100000,"currency":"MNT"}`
- **Oracle:** HTTP 200, `{"result":"ERROR_NO_FROM"}`.

#### TC-03 — Мөнгөн дүн тэг
- **Setup:** A болон B данс хүчинтэй, царцаагдаагүй; A дансанд 500,000₮ үлдэгдэлтэй.
- **Оролт:** `{"from":"A","to":"B","amount":0,"currency":"MNT"}`
- **Oracle:** HTTP 200, `{"result":"ERROR_BAD_AMOUNT"}`.

Тест кейсүүдийн oracle нь лабораторийн тодорхойлолт болон сонгосон алдааны эрэмбэд тулгуурласан.

### B3. Category-Partition ба PICT-ийн харьцуулалт

Category-Partition нь параметрүүдийн утгыг ангилж, бизнесийн дүрэм болон алдааны төрлийг тодорхойлоход тохиромжтой. Энэ аргаар тестийн хүлээгдэх үр дүнг хүн өөрөө тодорхойлдог учир алдааны семантикийг илүү нарийн илэрхийлж чадна. PICT нь параметрүүдийн хослолыг автоматаар үүсгэж, pairwise хамралтыг системтэй хангахад давуу талтай. Гэхдээ PICT-ийн greedy алгоритм хамгийн цөөн тестийн мөрийг заавал олохгүй. Мөн энгийн модельд олон алдаатай утга нэг мөрөнд орж, аль алдаа түрүүлж гарахыг тайлбарлахад хүндрэл үүсэж болно. IF хязгаарлалт болон сөрөг утгын тэмдэглэгээ нь ийм асуудлыг багасгахад тусалдаг. Гэхдээ тусгай happy path шаардлагатай бол гаралтад байгаа эсэхийг заавал шалгах хэрэгтэй. Энэ лабораторийн хамгийн их бодол шаардсан хэсэг нь алдааны давуу эрэмбэ, утгын хязгаарлалт болон хүлээгдэх үр дүнг хооронд нь нийцүүлэх байлаа.

## Дүгнэлт

Энэхүү лабораторийн ажлаар Category-Partition болон Microsoft PICT ашиглан тестийн загвар, хязгаарлалт, тестийн багцуудыг боловсрууллаа. 2-way, 3-way тест үүсгэх болон сөрөг утгуудыг шалгах замаар параметрүүдийн харилцан үйлчлэлийг системтэй тестлэх боломжтойг судлав. Автоматаар үүсгэсэн тестүүдийг чухал бизнесийн нөхцөлүүдээр нэмж шалгах шаардлагатай гэж дүгнэв.
